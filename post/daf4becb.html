线程dump与堆栈dump的区别

发表于 2026-05-25 更新于 2026-06-27 分类于 dump

线程dump与堆栈dump的区别 ~

一、概念对比

项目线程 Dump (jstack.log)堆 Dump (heap.hprof)
主要用途分析线程状态、执行路径分析内存使用和对象关系
排查场景死锁、线程飙高、CPU 飙高内存泄漏、OOM、大对象
适用场景应用响应慢、高 CPU内存不足、内存飙高
分析工具文本编辑器、grep、awkEclipse MAT、VisualVM、jhat

1.1 线程 Dump (jstack.log)

定义：线程 Dump 是 Java 应用程序运行过程中所有线程的当前状态快照，记录了每个线程正在执行的代码位置和线程状态。

文件特性：

  • 文件格式：文本文件（.txt、.log）
  • 文件大小：较小，通常在 KB 到 MB 级
  • 生成方式：使用 jstack 命令或 kill -3 信号
  • 生成速度：毫秒级完成，对业务影响极小
  • 包含内容：
    • 每个线程的线程 ID、名称
    • 线程当前状态（RUNNABLE、BLOCKED、WAITING 等）
    • 线程调用栈（正在执行的方法和行号）
    • 锁信息（等待和持有的锁）
    • 线程优先级、守护状态

1.2 堆 Dump (heap.hprof)

定义：堆 Dump 是 Java 堆内存的完整快照，记录了 JVM 中所有对象的实例、引用关系和内存占用信息。

文件特性：

  • 文件格式：二进制文件（.hprof）
  • 文件大小：较大（几 MB 到几十 GB）
  • 生成方式：使用 jmap 命令或 JVM 参数
  • 生成速度：较慢，可能触发 Full GC，可能导致服务暂停

二、核心功能对比

线程 Dump 核心要点

  1. 线程状态分析：

    • BLOCKED：线程在等待锁
    • WAITING/TIMED_WAITING：线程在等待通知
    • RUNNABLE：线程正在执行

  2. 死锁检测：

    • 查找 “waiting to lock” 信息
    • 分析锁的持有者和等待者
    • 识别循环依赖模式

  3. 性能瓶颈：

    • 分析调用栈耗时
    • 定位慢操作
    • 识别锁竞争

堆 Dump 核心要点

  1. 对象统计：

    • 按类的实例数量、大小排序
    • 大对象检测和定位

  2. 引用分析：

    • 对象引用关系
    • GC Roots 路径
    • 内存泄漏路径

  3. 内存分布：

    • 查看内存中最大的对象
    • 对象的分布
    • 类加载实例

三、实战应用

线程 Dump 适用场景

场景说明
系统响应慢但内存使用正常排查线程执行路径
CPU 飙高定位高消耗线程
大量线程堆积分析线程池配置
某些线程长期处于 WAITING 状态检查等待链
连接池出现积压（Recv-Q 积压）排查 I/O 瓶颈

堆 Dump 适用场景

场景说明
出现 OutOfMemoryError分析大对象占用
内存使用持续增长不释放排查内存泄漏
需要优化内存使用分析对象分布
怀疑存在内存泄漏验证泄漏路径

五、注意事项

性能影响

  • 线程 Dump：影响小，可频繁使用
  • 堆 Dump：影响大（应用暂停），谨慎使用

文件管理

  • 线程 Dump：文件小，便于存储和传输
  • 堆 Dump：文件大，需要足够的磁盘空间

分析工具

  • 线程 Dump：可用文本工具分析
  • 堆 Dump：需要专用分析工具（MAT、VisualVM、jhat）

总结

线程 Dump 和堆 Dump 是 Java 性能调优的两种互补工具，它们各有侧重：

  • 线程 Dump 是”线程的快照”：用于分析线程执行路径和线程状态，适合排查执行效率问题。
  • 堆 Dump 是”内存的快照”：用于分析堆内存占用和引用关系，适合排查内存使用问题。

在实际问题排查中，应根据具体情况选择合适的工具。如果遇到连接积压类问题，线程 Dump 通常是首选的分析手段。
