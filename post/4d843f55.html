Java 进程 CPU 高？用 jstack 定位问题

发表于 2026-05-25 更新于 2026-06-27 分类于 dump

Java 进程 CPU 飙升，用 jstack 定位问题代码，原来这么简单 ~

📋 完整流程

1️⃣ 确定 Java 进程 ID

先在终端里用 top 或 ps 命令找到 Java 进程 ID。

2️⃣ 找到占用 CPU 高的线程 ID

按 Shift+P 键 对 top 命令的输出进行排序，就能看到哪个线程占用了最多的 CPU。

3️⃣ 记录高 CPU 使用率的线程 ID

这个 ID 是十进制的，记下来备用。

4️⃣ 将线程 ID 转为十六进制

用 printf 命令就能完成转换。

5️⃣ 使用 jstack 生成线程快照

在终端里执行 jstack 命令，就可以生成线程快照文件。

6️⃣ 分析线程快照

用 grep 命令查找十六进制的线程 ID。

7️⃣ 解决问题

根据线程信息定位代码，分析并优化问题代码。

查看堆栈中的关键信息：

  • 类名
  • 方法名
  • 行号
  • 锁状态

⚠️ 关键点提醒

关键点说明
线程 ID 进制jstack 输出中的线程 ID 是十六进制的，必须转换
-l 参数jstack -l 显示锁信息，更全面
-A 20grep 时显示匹配行后 20 行，看到完整堆栈
定位代码查看堆栈中的类名、方法名、行号

🔍 常见 CPU 高的原因

原因说明解决方案
死循环代码逻辑问题，如 while(true)修复逻辑，添加退出条件
频繁 GC内存不足，老年代对象过多增加堆内存，优化对象创建
锁竞争大量线程等待同一把锁减少锁粒度，使用并发容器
序列化/反序列化大数据量处理优化序列化方式，使用更高效格式
正则表达式复杂正则回溯优化正则，避免贪婪匹配
数据库查询慢查询、全表扫描优化 SQL，添加索引
